# 资源生命周期设计

状态：2026-10-12 已实现并完成 Local 验证；公网、长时间运行和 Provider OS 内存硬限制尚未验收。证据见 validation.md。
本页补充 [设备协议](device-nodes.md)；不把首轮实验或真实执行成功当作长期资源稳定性证据。

2026-10-27 范围更新：正式定位归 [独立设备执行范围](standalone-v1.md)。当前保留按设备容量有界并行、单控制方与断线审批失效；Codex 复用原生 home，执行状态按 session 管理。下文具名旧 home 记录只描述当时实现，客户端共控与审批跨宿主重启恢复仍后置。

Codex 原生 home 与 dock 执行状态已分开。release/forget 不得删除用户 home、配置、插件、记忆或原生历史，也不能承诺业务方遗忘已传播到这些副本。保留原 run 身份、unknown 查回材料和用户目录保护，不预建新的 GC 或恢复平台；最新 Local 证据见 validation.md。

原生宿主接入只管理 dock 自身创建的进程和连接；接入已运行的客户端不授权 dock 关闭或重启用户应用。系统权限按实际宿主身份判定，不随设备配对或 ACP 连接自动继承。

## 容量检查扫描（2026-10-19）

prepare 与 execute 仍分别在维护准入段现查托管状态目录；原生 Provider 可以在两次检查之间写文件，不跨阶段或跨轮复用旧大小。只将 lstat 元数据读取按每批最多 32 项并行，同一批完成后才递归子目录，不增加递归层数对应的 I/O 并发。进入目录前重新 lstat，避免使用排队期间已变更的目录类型；不追随用户目录符号链接，文件与链接仍按实际 size 计数。

字节阈值、深度 64、条目 200,000、文件消失的 ENOENT 处理及其他 I/O 错误拒绝规则保持；目录读取和每批工作受同样遍历上限约束。现用容量准入仍不是 Provider 写入时的 OS 磁盘配额，不扩大原有保护承诺。优化与两次准入间新增超限数据的验证归 validation.md；未引入缓存、后台采样、线程或持久化索引。

## 观察文本合并（2026-10-16）

DeviceHost 为每个 run 建立一只通用观察 writer。标准 text_delta 只有具备稳定 messageId 且所有路由字段（含 stream/phase）相同时才合并；首片立即排发，后续约 100 ms 或文本达到 4 KiB 封批。单次原始观察继续受既有 256 KiB 限制；writer 最多持有 64 KiB 文本和 16 个观察批次，元数据另占空间，不能把该文本预算描述为整个进程内存上限。队列满时对生产者施加背压，不无限创建待确认批次。

文字入缓冲后返回，后台按批执行原有本地 observe 持久化和 callback，并保留真实回执；入缓冲不是持久化或 Core 接受。100 ms 是正常合并窗口，慢回执时排队可延长未持久化观察的时间。该窗口只涉及临时显示内容，原生完整 final 与 run 终态证据不从缓冲推导。

非文本观察和消息/阶段变化前冲刷已有文本，保留观察顺序。原生审批、审批送达报告、授权工具调用与取消保持原独立控制路径；控制请求只封住当时文本批次，不等待观察网络回执，也不宣称跨通道全序。Provider 返回后先等待本轮已接受观察完成，再保存设备终态；本地持久化错误沿既有 catch 转为 unknown。远端观察 callback 失败仍沿现有持久观察/调用方未知处理，不重放副作用。

writer 使用 DeviceHost 外层执行 signal；取消/关闭释放 timer、停止后续观察发送并唤醒背压等待，不阻止 Provider 记录真实取消或完成证据。它不拥有原生会话，不新增传输协议或恢复队列。实现与真实部署、模拟边界和 Owner 聊天验收分别登记在 validation.md。

## 目标和范围

让一台设备的 Daemon 能长期运行，同时限制 harness-dock 自己持有的缓冲、进程和历史数据。
本轮先处理现有设备 Daemon 与连接 SDK，不创建账号系统、任务平台、容器平台或数据库服务。
独立控制端作为同仓库的 `apps/server`，与 ServerClient 和 调用方应用 出站接入同批实现；真实公网部署单独验收。

- Daemon 拥有 Provider 进程、原生会话、执行身份、结果和本机文件。
- 连接拥有 socket、心跳、待响应 RPC 和发送缓冲；断开只销毁连接资源。
- 调用方拥有业务任务、用户审批与结果收存。调用方的任务期限不能代替通用 Daemon 的资源边界。
- 确认完成、观察数据到期、连接断开、请求取消是不同事实。
- 自动清理不得再次执行旧 runId，不得把未知结果改成成功、失败或确认取消。

## 实施前审计

| 资源 | 实施前行为 | 本轮处理目标 |
| --- | --- | --- |
| 设备连接 | 静态配对、心跳、请求超时、断开释放 pending | 待发送总量、并发 handler、pending 数量均无硬限制 |
| 执行 | 每设备一轮，finally 释放活动对象 | 完成的审批报告 Promise 仍留在数组到整轮结束 |
| Codex 进程 | 单个暖会话，切换或退出时关闭 | 无空闲回收；支持从原生 thread 冷续接 |
| Lobi/DeepSeek 进程 | 每轮进程在 finally 关闭 | 复用现有释放，不新增暖会话机制 |
| SQLite | 事件分页 100 条；执行结果持久化 | startup/unresolved 全表载入 JS；无索引化状态查询和历史清理 |
| 输出 | 部分 stderr 已有 16 KiB 限制 | ACP 文本拼接、Codex 消息和文件回读缺少完整总量限制 |
| 文件 | release 删除指定 run 的输出目录 | Skill 缓存、Provider home、原生历史没有会话到期规则 |
| Daemon 日志 | 后台 fd 追加；logs 命令仅限制读取大小 | 运行期无轮转，重启前轮转不能解决常驻增长 |

## 首版默认预算

数值是首版默认配置，不是已测得的容量或整个进程 RSS 上限。配置由节点所有者设置，远程执行请求不能抬高它。

| 对象 | 初始值 | 超限行为 |
| --- | --- | --- |
| 暖进程空闲 | 10 分钟 | 关闭本节点拥有的空闲 Provider 进程 |
| 普通 RPC | 沿用 30 秒；工具/审批沿用具名更长时限 | 结束等待，不推断远端执行失败 |
| 每连接 pending RPC | 32 | 拒绝继续积压并关闭该连接 |
| 每连接并发入站 handler | 16 | 关闭该连接，其他设备继续工作 |
| 单条 WS 消息 | 沿用 64 MiB | 拒绝连接消息；文件仍受更小的实际文件限制 |
| 每连接处理中入站字节 / 待发送字节 | 各 64 MiB | 关闭慢或过载连接，不无限排队 |
| 本地 socket 写入等待 | 60 秒 | 关闭连接并拒绝 send Promise |
| 单轮累计回答正文 | 8 MiB UTF-8 | 中止继续收集并请求取消，结果按上游证据或 unknown 处理 |
| 单条可展示过程内容 | 256 KiB UTF-8 | 显式记录观察超限，不作为完整正文继续发布 |
| 单轮持久化过程 | 32 MiB，最多 10,000 条 | 明示过程已截断；不截断审批、工具请求或权威结果 |
| 已确认终态的详细过程保留 | 7 天 | 删除过程内容，保留去重身份与必要终态摘要 |
| 本地 SQLite + 执行管理目录 | 软预算 512 MiB | 先回收合格历史；无法降到预算以下则停止新执行准入 |
| 受管理的 Daemon 日志 | 10 MiB × 3 个文件 | 运行中轮转并删除最旧分片 |
| 节点执行身份数量 | 100,000 个 | 停止新身份准入，明确维护提示，不自动遗忘后重复执行 |

当前实际文件限制为每文件 8 MiB、总计 16 MiB、最多 64 个文件；Base64 后约 22 MiB。
64 MiB 传输上限不能被直接当作 64 MiB 内存上限，JSON 编解码还会产生临时副本。
512 MiB 是节点管理数据的准入软预算，不是用户工作目录、Provider 原生进程或操作系统的硬隔离保证。
执行期间跨过预算时允许写入小型终态/unknown 元数据，随后停止新准入；不能因写库失败而丢失已开始执行的身份。
真正磁盘写满属于故障：保留已落盘 running，启动后按 unknown 处理，不能自动重派。

## 1. 连接内存生命周期

在 protocol 内维护无 ws/NestJS 依赖的预算定义；连接计数由各端实际 socket 生命周期持有，不新增 package。

1. `request()` 发出前申请 pending 配额，finally 归还；断开结算这一代连接的 pending 和 send。尚未结束的入站 handler 及字节预算由跨连接稳定的 DevicePeer/DeviceConnection 持有，直到实际 settled 才释放，防止反复重连绕过上限。
2. 入站请求和 notification 按实际收到的 UTF-8 字节数及 handler 数量申请配额，结束即释放。
3. response 不占 request handler 配额，避免执行等待审批回复时因配额占满形成死锁。
4. 两端一致拒绝 JSON-RPC batch 数组，禁止一帧绕过并发计数；显式关闭 WS 压缩。
5. send 同时检查序列化大小、已预留字节和 `bufferedAmount`。发送占用在本地写回调后释放，不只在入队时释放。
6. 写回调另有 60 秒 deadline；已安装 json-rpc-2.0 的 request 会先等待 send，因此单靠 RPC timeout 不足以取消卡住的发送。
7. 写回调仅证明本地发送完成，不证明审批被 Provider 接收，更不证明整轮完成。
8. 过载关闭该连接；Daemon 继续持有执行。重连查询持久状态，不自动重发 prompt、工具或审批。尚未确认投递的审批当次失效，节点按 deny 处理，实际投递仍由原生 ACK 确认；不恢复旧 allow。旧 callback 必须响应 AbortSignal，未 settled 的 callback 继续占用入站配额。

审批投递报告改为只保存尚未完成的 Set，完成即移除并有在途数量上限；不保留整个长任务的 settled Promise 数组。

## 2. Provider 和会话生命周期

DeviceHost 统一持有一只 `.unref()` 空闲定时器。Provider close、prepare、release、probe、reconcile 与 execute 共用互斥维护状态。
定时器触发时先同步取得维护权，再 await close；旧 timer generation 不得关闭新会话。Daemon close 禁止新准入，等待正在进行的维护后再关闭 Store。
等待人工审批属于活动执行，不触发空闲回收。仅有心跳不刷新会话使用时间。

| Provider | 回收后能否续接 | 契约 |
| --- | --- | --- |
| Codex | 支持从磁盘重新载入原 thread；新增回收路径已通过 Local 真实验证 | 保留 Provider home；下一轮明确 load 原 thread，不创建替代会话 |
| Lobi/DeepSeek | 依现有 ACP load 能力 | 沿用当前每轮关闭与显式续接错误，不加入新 fallback |

进程回收与会话历史删除分开。首版不自动删除当前可续接的原生会话，也不以 idle timeout 结束 调用方应用 的任务或会话事实。

## 3. SQLite、历史和幂等身份

- 用带索引的状态查询直接取 unknown runId；启动时以 SQL 批量将 running 改成 unknown，避免把全部结果载入 JS。
- 过程以 `(run_id, sequence)` 索引分页，同时限制每页字节数；仅限制 100 条不足以限制大 payload。
- 保存创建/终态/释放时间和观察是否完整的信息；所有时间由 Daemon 本机记录，不信任控制端传入的到期时间。
- 7 天清理只针对已确认终态且调用方显式 release 的详细数据；release 未到达则保留，空间不足会阻止新准入并提示具体原因。
- confirmed terminal 的完整结果与详细过程到期后，可压缩为小型永久摘要：runId、输入摘要、终态、Provider 身份、详情过期标志。
- 重复旧 runId 仍命中摘要；若正文已经清理，返回 execution_details_expired，不再次启动 Provider。
- running、unknown、未完成审批、未收存输出不参加自动删除。unknown 会阻止新执行，必须先只读查回或人工明确处理。
- preparation 身份也必须保留，避免旧 prepare/runId 被当成新操作。未执行 preparation 设明确租期，过期后保留拒绝重用的摘要。
- 过期或截断必须在查询结果和事件接口中明确暴露。不得把缺失事件伪装成“没有调用工具”，也不能悄悄从中间继续返回完整过程。
- Store 表结构变更使用单次事务迁移并验证迁移后去重，不以重置用户节点数据作为升级方式。

自动 GC 首次在启动恢复后、后续每分钟在节点空闲时运行，每次最多 100 项；各批次间让出事件循环。不按每次文本增量扫描全库。
删除后优先复用 SQLite 空闲页；只有无执行且空闲页比例确有需要时做受控压缩，不把每次 GC 变成整库 VACUUM。

## 4. 文件与日志

- 保留现有 run 输出目录 release 安全校验，只操作本节点管理的具名目录；用户 cwd 和原始 Provider 登录目录不参与 GC。
- Skill 缓存只有在所有引用 run 已释放、原生会话显式结束或不可续接后才可删除。
- 原生会话目录需要显式 end/forget 入口才能清理：有 active、unknown 或未收存输出引用时拒绝；先持久化会话已结束与不可续接，再删除具名目录。执行去重摘要继续保留。unknown 所需的查回材料不能随定时器删除。
- 历史原生目录触及软预算但仍被引用时，拒绝新准入并返回需要处理的会话，而不是自动删会话或自动新建替代会话。
- 所有 evidence/回读文件先验证类型、身份与大小，再有界读取；超大文件仅回传受限元数据；符合既有文件发布上限时可发布，否则明确超限，不能全部读入过程文本。
- 后台日志由 Daemon 内持有轮转 sink；前台 stdout 可交给外部服务管理器。不要增加一个仅为日志存在的守护进程。
- 已有有界 stderr 保持现状；连接日志不打印配对凭据；轮转分片权限保持 0600。轮转不提供任意 Provider 文本的通用脱敏器。

## 5. 超限与失败语义

| 发生点 | 处理 |
| --- | --- |
| 准入前预算不足 | 返回 node_storage_full 或 resource_exhausted，不产生 Provider 副作用 |
| 执行中只有观察记录超限 | 标记 history_truncated，权威结果与审批/工具通路继续遵守各自预算 |
| 回答正文或本轮必要 payload 本身超限 | 请求停止执行；等到上游确认才写确定终态，否则保持 unknown |
| 连接发送积压或并发超限 | 仅关闭该连接，审批/工具按失败关闭；不把所有断线等同自动取消 |
| 响应丢失、控制端重启 | 设备保留去重记录；控制端按原 runId 查询，不自行重派 |
| 详细结果已过期 | 返回终态摘要和明确过期标志，不伪造 final_answer |

观察数据截断只能影响技术过程展示，不能更改 final_answer 正文后仍声明 exactFinalAnswer。
资源保护不得绕过 Core 的审批决定、Claim/fencing 或业务终态。

## 6. 独立控制端的项目边界

同仓库增加 `apps/server` 独立部署入口。

```text
调用方应用 / 其他调用方 -- client SDK --> apps/server <-- 长连接 -- 设备 Daemon
```

DeviceController 继续作为 server 内部的设备连接宿主；ServerClient 是中台使用的出站 SDK。调用方应用 bridge 使用后者，独立 server 拥有部署入口与访问范围校验。

server 负责设备配对与撤销、调用方对设备的访问授权、连接和请求路由。首版单进程，使用 0600 私有 JSON 保存技术配置，重启应用变更；
不复制 调用方的业务数据或任务账本，也不复制整套设备执行账本。没有控制端持久化的设备过程，在设备离线时明确不可查询。
活跃连接和 pending 仍用上面的预算；已注册设备是持久配置，离线本身不自动注销。设备删除/撤销时同时释放关联处理器和连接。
服务实施时固定设备与调用方总连接数上限，再从实际内存压力调整；首轮不引入 Redis、集群调度或额外 SSO。

## 实施顺序与最短验证

1. **现有数据路径**：状态索引化查询、分页字节上限、settled Promise 释放、回答/文件读取上限。
2. **连接保护**：两端统一计数和发送 deadline，保持断线不重派。
3. **空闲进程**：统一维护互斥与 timer；Codex 验证冷续接。
4. **存储清理**：持久时间与摘要、GC、显式 end/forget 入口、日志轮转、总容量准入；同步设备协议版本及调用方过期/截断展示。
5. **独立 server**：实现同仓 apps/server、远程 SDK、调用方应用 适配，完成本机链路；实际家庭跨网单独验收。

统一修改后再集中运行已有测试；优先扩展 device-controller、device-host、embedded 等现有套件，不新增完整产品矩阵。
必须证明：重复身份在清理后不再次执行；unknown 不被清理；活动执行/审批不被 idle 关闭；回收竞态不产生两个进程所有者；
慢连接只影响自己的节点；RPC response 不因 handler 配额死锁；Codex 回收后仍 load 原 thread；超限不伪造成功。

短时合成实验已记录 server/SDK RSS 与请求计数，真实 Codex 实验记录暖态、回收和冷续接的进程树。未采集长期磁盘曲线、真实慢网络发送缓冲或 Provider RSS 压力曲线。
固定模型的真实 Codex 仅验证新增的空闲回收/续接链。稳定曲线必须来自运行证据，不能由测试条数推定。
首版预算不承诺第三方 Provider 进程的 OS 级内存硬上限；如观察到其自身持续增长，再采用对应 OS 服务管理限制。

## 独立 server 首版执行契约（已授权实施）

首版采用私有配置文件，不引入数据库服务或在线管理 UI。`apps/server` 运行设备入口（默认 48518）和应用入口（默认 48519）；两者非 loopback 均要求有证书校验的 WSS。配置包含 nodes 的设备凭据以及 clients 的独立应用凭据和 nodeIds 访问范围，最大 128 个节点、16 个应用，每节点只归一个应用控制；重复归属在启动时拒绝。配置或撤权后重启生效，启动先完成全量校验，不能半生效。

应用 SDK 主动连接 server；server 只转发具名设备方法及所属节点的 callback。设备/应用连接均校验身份、协议版本和独立凭据，拒绝浏览器 Origin、重复在线连接及未授权 nodeId。应用断线时旧 callback/审批失效，节点执行继续并可查询；不得重派 prompt。server 重启只恢复配置和在线发现，不保存或重新执行任务。查询离线设备明确报错。当前连接宿主 DeviceController 继续作为 server 的内部组合能力；调用方应用 迁到远程 ServerClient，不再自己开放设备监听端口。

部署提供单进程启动、TLS 配置、环境无关的安装产物和健康检查；真实云地址/证书及家用设备仍单独验收。
