# 界舟桌面端设计评审

> 2026-11-06 整体复审见 [产品、交互、视觉与实现整体评审](product-experience-review.md)。本文保留此前桌面局部调整记录；新的状态语义、页面职责和整改顺序以整体复审为准。两份文档均不代表整改已经全部实现。

范围：GPUI 桌面端的主窗口、菜单栏速览、接入、Harness 详情和维护，以及下载和帮助文档的交接。以 macOS 界面和仓库锁定的 GPUI Kit 0.9.0 为依据。未接入、异常和恢复分支的结论来自源码；Windows 原生表现与跨机接入仍需实机验收。

桌面端的定位是让设备持有人确认三件事：**接入了哪个服务器、本机安装了哪些 Harness、遇到问题下一步做什么。** 已安装、服务器在线和响应测试通过是不同证据，不合并成“已就绪”。同一个答案不重复拆成页标题、说明、区块标题、字段名和标签。

## 固定的产品结构

- 侧栏只有「概览」和「设置」。接入与 Harness 详情是概览的子页，用内容区面包屑返回；设置不再切换窗口或增加页面内返回按钮。
- 概览先给出连接状态及对应操作，再显示本机 Harness 列表。断开留在当前连接行。
- 设备接入优先使用邀请链接，配对文件是替代入口，旧连接恢复默认收起。恢复不再占据未接入的设置页。
- 设置只显示适用项目：未接入时显示常规偏好；已配置后增加自动连接、连接服务、诊断和技术信息。日志入口打开文件位置。
- Harness 详情先表达真实前置条件；响应测试是可选操作，使用模型额度，不能作为连接成功的必要条件。

参考 [shadcn Sidebar blocks](https://ui.shadcn.com/blocks/sidebar) 的稳定侧栏与 inset 内容结构，以及 [Tailscale 设备偏好](https://tailscale.com/docs/features/client/manage-preferences) 对设备设置和管理端职责的划分。采用这些结构原则，实际控件仍由锁定版本 GPUI Kit 提供。

## 按页面调整

| 页面 | 当前问题 | 建议成稿 |
| --- | --- | --- |
| 侧栏 | 导航位置反复迁移，只有两项却加了重复的分组标题。 | 固定使用 `Sidebar` / `SidebarMenu` 的概览、设置两项；不加空分组或填充入口。标志、品牌名、版本是一组静态内容。 |
| 本机概览 | 连接状态、入口和任务在本机执行的说明重复；“已安装”的数量和每行的“已安装”也重复，检测未完成时还可能建议安装。 | 首屏先显示连接状态与一个对应动作，再列 Harness。行右侧固定放进入详情的箭头，日常成功态不贴标签；未检测到、已停用、检测待确认需要明确标出。版本与最近一次测试为次要信息。 |
| 远程链接 · 未接入 | 邀请输入、帮助、配对文件缺少主次；核对时服务器和目录可能被截断。 | 保留“确认”和“选择文件”。一行邀请输入与确认，一行备选文件；用短提示说明文件来自管理员。核对页只展示服务器、执行目录和确认动作，长地址、长路径可完整查看。自定义 CA 放在“高级选项”。 |
| 远程链接 · 已接入 | 旧版状态被拉成满宽色条。现在按钮已并入卡片，但通用描述、“当前服务器”标题和卡片分成三层；灰色小标签像禁用控件，“执行设备：本机”又抢了一行。 | 页标题下直接显示一个连接区：状态与服务器地址在同一组，右侧“断开”。已连接时无需重复解释本机执行，无需第二个标签边框，也无需专门的操作条。服务已停止或状态异常时才显示原因和对应下一步。 |
| Harness 详情 | 测试结果、时间、说明、按钮、额度提示各占一段；程序路径和测试 ID 用独立的字段表堆叠，成功记录还可能出现尾随分隔符。 | 先显示 Harness 名称和检测结果；用“上次测试通过 · 1 天前”一行表达结果与时间。测试入口旁只留一条额度提示，失败时就地说明原因。技术信息用一份 `DescriptionList`；字段有值才提供复制，测试记录 ID 与错误代码分字段展示，DeepSeek 专属说明只在其详情显示。 |
| 设置 | 偏好、后台启停混在双列 `Form`；“停止服务”被撑满值列，运行说明落在按钮下。排查区又嵌套折叠框，诊断、版本维护和日志混在一起。 | 第一组是“外观 / 登录后自动连接”；每行左侧说明、右侧实际控件。第二组先显示后台状态，次级启停按钮保持内容宽度。“检查连接环境”和“技术信息与日志”直接可见；只有有可切换版本时才显示版本维护，显示当前与目标版本。折叠最多一层。 |
| 菜单栏速览 | 它和首页都显示连接与 Harness，但文案、品牌和未知状态不同；更多提醒会让速览变成小号设置页。 | 使用同一份连接、安装、待处理状态映射。日常只保留连接、Harness 列表和设置入口；有行动需要时只露出一个明确动作，交回主窗口完成。 |
| 下载与帮助 | 公开 Swift 版、GPUI 源码候选以及 Windows 实验路径并存。不同入口引用相同版本号时容易把按钮、平台与发行包看成同一套。 | 下载和步骤按发行包标明前端、系统要求和支持状态；预览版帮助直接定位对应流程。保留设备使用者、服务管理员、应用接入者的分工；桌面端帮助只引向设备持有人当前要完成的步骤。 |

## 组件边界

- **真实复用。** 已用 `Sidebar`、`List` / `ListItem`、`Form` / `Field`、`GroupBox`、`DescriptionList`、`Accordion`、`Button`、`Input`、`Switch`、`ButtonGroup`、`Clipboard`、`Alert`、`Empty` 和库的浅深主题。主窗口导航、设置、技术信息和维护页也都有应用自己的内容排列。`Form` 和 `Accordion` 提供容器，无法替我们确定信息的主次。
- **合理组合。** 页面框架只负责共用内容边界、滚动和标题；表单只承载实际输入；一组只读字段用同一个 `DescriptionList`；`List` 给真正可进入的条目。避免每个字段各套一个容器，避免在折叠框内再包一个折叠框。只有库没有对应布局时才使用 `h_flex` / `v_flex` 组合现成元素。0.9 的整页 `Settings` 自带第二层导航，两项导航的应用壳内不再嵌入。
- **对齐和节奏。** 页标题、区块标题、列表外框共用左边界，常规页面共用宽度，输入框单独限制阅读宽度。保持 24 px 页边距、20 px 区块间距、12–16 px 内边距、4–8 px 行内间距的层级。段落与其控件靠近，同级内容有相同内边距。路径用等宽；标题、普通状态和动作沿用组件默认字号。
- **按钮和状态。** 一个状态只突出一个可执行的下一步。主要动作使用 Primary，次级使用有边框的 Default，刷新、帮助、复制等低频操作使用 Ghost 或组件默认样式。按钮按内容宽度，同一排与输入框同高；颜色与尺寸按库的变体。状态优先用短文字，异常有原因，进行中有进度反馈。保留危险操作的原生确认。
- **键盘与窄窗。** 侧栏入口、Harness 行、展开标题、表单按钮均能用键盘到达并激活；展开按钮有可朗读的名字。页面切换将焦点移到新内容，返回后回到发起点。正常和 720×520 最小窗口中，按钮不挤压核对所需的信息。测试长地址、长路径、缩放、浅深色和菜单栏弹窗。

## 交互问题优先修复

1. **状态要可信。** 已接入、连接在线、后台运行和 Harness 已安装是四件事。概览、远程链接、设置、托盘从同一状态模型派生展示；检测未知、过期与明确未检测到分开。对应的状态读取成功后清除旧的读取报错。刷新不打断正在编辑的输入与焦点。
2. **恢复原操作要清楚。** 正常提交显示“正在提交”；只有未收到确切结果时才提示“待核对”。接入不明先给核对或继续原接入；避免在禁用表单上方再堆一排竞争的按钮。收到另一份邀请可忽略。断开仍明确说明停止收任务及关闭自启，活动和待核对任务仍有保护。
3. **临时信息有归属。** 换服时旧诊断和日志不应混进新连接，原始记录可在原位置保留。邀请输入与自定义 CA 跟随当前接入草稿，重试同一草稿保留，换来源时重新核对。

## 修改后的验收要求

页边距与区块间距使用 `theme::metrics` 的共享值，避免每次产品调整重新定义布局。接入表单最大宽度 520 pt；辅助说明与帮助链接使用相同的小字号。列表保持已有 56 pt 行高、36 pt 图标槽、18/16 pt 文本行高与 2 pt 主副标题间距。

验收用浅色和深色的真实 GPUI 窗口对照，覆盖未接入、邀请核对、在线、未检测到、测试前置条件和设置。窄窗重点检查主题控件、诊断操作是否挤压文案。需要触发断开、提交、版本切换的验收使用隔离配置。编译和测试通过不等于已完成视觉验收；发布包、运行中的进程与所查看的构建必须一致。
